# Сетевой режим: один сервер на все устройства

Тот же бинарник умеет работать двумя способами:

- **stdio** (по умолчанию) — Claude (или другой MCP-клиент) запускает сервер подпроцессом на вашей машине. Просто, но работает только там, где стоит бинарник и откуда видна ФГИС.
- **Streamable HTTP** (`--http` / `RST_HTTP_ADDR`) — сервер живёт на VPS, к нему подключаются claude.ai, телефон и агенты.

## Главное условие: российский адрес

ФГИС «Аршин» отвечает только российским адресам. С зарубежного VPS (и через зарубежный VPN) соединение не отклоняется, а висит до таймаута — сервер при этом нормально стартует и проходит `/healthz`, а каждый инструмент отказывает через 25 секунд.

Два рабочих варианта:

1. VPS в России — ничего настраивать не нужно.
2. VPS где угодно + HTTP(S)-прокси с российским адресом: `HTTPS_PROXY=http://user:pass@host:port` в `deploy/rst-metrology-mcp.env` (или `RST_HTTPS_PROXY=… ./deploy.sh <домен>` при развёртывании).

`./deploy.sh` проверяет доступность ФГИС с машины и предупреждает, если её нет.

## На VPS: одна команда

Нужен VPS с Docker и A-запись домена на его адрес:

```
rst-mcp.example.com    A    <адрес VPS>
```

Дальше:

```bash
git clone https://github.com/MainAlexStark/rst-metrology-mcp
cd rst-metrology-mcp
./deploy.sh rst-mcp.example.com
```

Скрипт:

1. проверит, отвечает ли ФГИС с этой машины;
2. заведёт сеть `mcp-network`;
3. поднимет общий Caddy в `/opt/infrastructure`, если его там ещё нет;
4. впишет домен в его `Caddyfile` между маркерами `# >>> rst-metrology-mcp` и `# <<< rst-metrology-mcp` — соседние блоки (ozon-seller-mcp, k8s-mcp) не трогает;
5. придумает пароль владельца и статические токены, положит в `deploy/rst-metrology-mcp.env` с правами 600;
6. соберёт образ и поднимет сервер;
7. дождётся `200` от `https://<домен>/healthz`.

Повторный запуск ничего не перевыпускает: иначе отвалились бы уже подключённые устройства.

## Обновление

```bash
./deploy.sh update
```

`git pull --ff-only`, пересборка, ожидание `/healthz`. Если новая версия не ответила — скрипт возвращает прежний коммит и поднимает его.

## Остальные команды

```bash
./deploy.sh status     # что запущено и отвечает ли сервер
./deploy.sh logs       # журнал сервера
./deploy.sh secrets    # снова показать пароль и токены
./deploy.sh restart
./deploy.sh down
```

## Подключение

Адрес для клиентов — `https://rst-mcp.example.com/mcp`. Как пройти экран согласия и выпустить токен для агента — [`OAUTH.md`](OAUTH.md).

Проверить, что сервер видит ФГИС, — инструмент `rst_selftest` или с самой машины:

```bash
docker exec rst-metrology-mcp /rst-metrology-mcp --check
```
