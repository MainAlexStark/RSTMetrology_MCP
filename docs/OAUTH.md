# OAuth: подключение устройств

Сетевой сервер не стартует без авторизации: открытый порт, через который
любой гоняет запросы к ФГИС с адреса вашего VPS, — это в лучшем случае
блокировка этого адреса Росстандартом за превышение лимита частоты.

OAuth 2.1 — основной способ для людей. Сервер сам себе authorization
server: пользователь один (владелец), «вход» — проверка одного пароля.
Динамическая регистрация клиентов, PKCE, экран согласия, токен на час,
refresh, поштучный отзыв подключений.

## Как это выглядит

```
Claude / клиент             rst-metrology-mcp
  │                            │
  ├─ запрос без токена ───────►│
  │◄──── 401 + где метаданные ─┤
  │                            │
  ├─ читает метаданные ───────►│
  ├─ регистрируется (DCR) ────►│
  │                            │
  ├─ открывает браузер ───────►│  ← вы вводите пароль
  │                            │    и выбираете права
  │◄──── код авторизации ──────┤
  ├─ меняет код на токен ─────►│
  │◄──── токен на 1 час ───────┤
  │                            │
  ├─ работа с токеном ────────►│
```

Пароль вводите только вы и только в этот момент. Клиент его не видит:
он получает код, а код без вашего подтверждения не выдаётся.

Это способ для ЛЮДЕЙ — вас самих, вашего личного ноутбука или телефона.
Для агентов и скриптов (машина без человека в цикле) есть отдельный способ —
статический токен, см. ниже.

## Настройка

### 1. Пароль владельца

При развёртывании через `./deploy.sh` делать ничего не нужно: пароль придумывается там же и печатается один раз в конце. Показать снова:

```bash
./deploy.sh secrets
```

Если разворачиваете руками — положите пароль в `RST_OWNER_PASSWORD`. Сервер посчитает из него PBKDF2-хеш при старте; сам пароль он никуда не записывает.

Открытый пароль в окружении нежелателен даже в файле с правами 600? Тогда посчитайте хеш заранее и положите в `RST_OWNER_PASSWORD_HASH` — заданный хеш имеет приоритет:

```bash
rst-metrology-mcp --hash-password
```

Пароль читается со stdin, а не из аргумента: аргументы видны через `ps` и остаются в истории оболочки.

### 2. Переменные окружения

```bash
# Внешний адрес сервер — он же включает OAuth.
RST_PUBLIC_URL=https://rst-mcp.example.com

# Пароль владельца из предыдущего шага. Хеш сервер считает сам.
RST_OWNER_PASSWORD=…

# Где хранить клиентов и токены. Файл переживает перезапуск —
# иначе каждый рестарт отключал бы все устройства.
RST_OAUTH_STORE=/var/lib/rst-metrology-mcp/oauth.json
```

### 3. Проверка

```bash
curl -s https://rst-mcp.example.com/.well-known/oauth-protected-resource | jq
```

Поле `resource` должно **точно** совпадать с адресом, который вы будете
вводить в клиенте. Расхождение в одном слэше ломает подключение,
а сообщение об ошибке будет невнятным.

## Подключение устройств

Адрес без всяких секретов:

```
https://rst-mcp.example.com/mcp
```

**claude.ai, Desktop, мобильное приложение:** Настройки → Connectors →
Add custom connector, вставить адрес. Откроется браузер с экраном
согласия.

**Claude Code:**

```bash
claude mcp add --transport http rst-metrology-mcp https://rst-mcp.example.com/mcp
```

### На экране согласия

Показывается, какое приложение просит доступ, куда оно вернётся,
и галочки прав:

- **Чтение** (`rst:read`) — все инструменты сервера: поиск и карточки
  поверок, проверка прибора, реестр типов СИ.
- **Изменение** (`rst:write`) — зарезервировано. Пишущих инструментов
  у сервера сейчас нет; оставляйте выключенным.

## Управление подключениями

Кто сейчас подключён:

```bash
docker exec rst-metrology-mcp /rst-metrology-mcp --grants
```

Отозвать одно подключение (по началу идентификатора выдачи):

```bash
docker exec rst-metrology-mcp /rst-metrology-mcp --revoke 3f2a9c
```

Устройство теряет доступ немедленно, остальные продолжают работать.

## Статические токены — для агентов и автоматизации

Экран согласия рассчитан на человека. Агент, который работает сам
(например, разбор заявок на поверку), предъявляет статический токен:

```bash
rst-metrology-mcp --gen-token
```

Значение кладётся в `RST_TOKEN_READ` на сервере и в заголовок
`Authorization: Bearer …` у клиента. Такие токены не истекают
и отзываются только сменой значения — держите их только для машин.

## Если не подключается

**Клиент не видит сервер.** Проверьте, что `401` возвращается
с заголовком `WWW-Authenticate`, где есть `resource_metadata`:

```bash
curl -si -X POST https://rst-mcp.example.com/mcp -d '{}' | grep -i www-authenticate
```

**Ошибка на этапе регистрации.** `/oauth/register` принимает JSON,
`/oauth/token` — форму. Если между ними прокси, переписывающий
Content-Type, ломается один из двух.

**Метаданные не сходятся.** Поле `resource` обязано совпадать
с введённым адресом посимвольно.
