# Инструменты

Все инструменты только читают. Имена — договор с агентами: менять их без нужды нельзя.

## Поверки

### `search_verifications`

Поиск записей о поверке в ФГИС «Аршин» (`GET /eapi/vri`).

| Аргумент | Что это |
|---|---|
| `search` | полнотекстовый поиск, допускает `*` |
| `mit_number` | регистрационный номер типа СИ, `16078-05` |
| `mit_title`, `mit_notation`, `mi_modification` | наименование, обозначение, модификация |
| `mi_number` | заводской номер экземпляра |
| `org_title` | организация-поверитель |
| `year` / `date_from`, `date_to` | период (`YYYY-MM-DD`, принимается и `dd.mm.yyyy`) |
| `applicability` | `any`, `applicable`, `inapplicable` |
| `sort`, `rows` (≤100, по умолчанию 20), `start` | порядок и страницы |
| `filters` | прочие параметры API как есть |

Хотя бы один фильтр обязателен. Без периода ФГИС ищет только текущий год: при заданном `mi_number` сервер подставляет последние 10 лет, в остальных случаях честно пишет в `_note`, что смотрел текущий год.

Ответ: `count`, `returned`, `next_start`, `period`, `items[]` (`vri_id`, `org_title`, `mit_number`, `mit_title`, `mit_notation`, `mi_modification`, `mi_number`, `verification_date`, `valid_date`, `result_docnum`, `applicability`). Даты приведены к ISO.

### `get_verification`

Карточка поверки (`GET /eapi/vri/{vri_id}`). Принимает `vri_id` или ссылку на карточку на сайте.

Отдаёт плоскую сводку (`summary`): тип и модификация, заводской номер, год выпуска, поверитель, владелец, дата и срок, методика, вид поверки, `applicable` (true — свидетельство, false — извещение), номер свидетельства/извещения, статус публикации. Плюс `valid_today` и `card_url`.

`follow_versions` (по умолчанию да) — модифицированная запись заменяется действующей версией, пройденная цепочка — в `versions`. `include_raw` — исходный документ ФГИС (эталоны и средства поверки).

### `check_instrument`

Вердикт по прибору: `mi_number` (обязательно), `mit_number` или `mit_notation` (желательно), `on_date`, `years_back`.

| Вердикт | Значит |
|---|---|
| `valid` | последняя поверка пригодна, срок не истёк (`valid_until`, `days_left`) |
| `expired` | срок истёк |
| `inapplicable` | последняя поверка — извещение о непригодности |
| `cancelled` | последняя запись аннулирована |
| `unknown_term` | пригоден, но срок в реестре не указан |
| `ambiguous` | с этим номером несколько типов СИ — повторить с `mit_number` из `types` |
| `not_found` | записей нет за период |
| `not_found_yet` | ФГИС не дала просмотреть период целиком (широкий запрос, лимит запросов) |

Как работает: один запрос за весь период; если ФГИС отвечает «слишком широко» — по годам от свежего к старому до первой записи. Заводские номера сравниваются после нормализации (регистр, пробелы, похожие кириллические и латинские буквы). По последней записи запрашивается карточка — ради аннулирования и срока. Не больше `RST_MAX_REQUESTS_PER_CALL` запросов к ФГИС на вызов.

## Типы СИ

### `search_types`

Поиск в реестре утверждённых типов (`GET /eapi/mit`): `search`, `rows`, `start`, `filters`. Элементы отдаются как пришли.

### `get_type`

Карточка типа (`GET /eapi/mit/{mit_uuid}`). Принимает `mit_uuid`, ссылку `mit_url` из карточки поверки или регистрационный номер — по номеру сервер сначала ищет тип и берёт его идентификатор.

## Диагностика

- `rst_status` — адрес API, режим, потолок ответа, лимит запросов на вызов.
- `rst_selftest` — по одному запросу в раздел поверок и раздел типов; если не ответил никто, прямо говорит, что дело в доступе к ФГИС (российский адрес / прокси).
